# 청약딱 — 내 조건 맞춤 청약 필터 (전국판)

청약홈(applyhome.co.kr)의 **전국 공고**를 **무주택·유주택 여부, 거주지, 청약통장 예치금**으로
걸러서 "지금 신청 가능한 공고"와 "안 되는 이유"를 같이 보여주는 정적 웹앱입니다.

- 데이터 기준일: **2026-11-25** — 청약홈 활성 공고 **38건 / 전국 12개 시도**
  (APT 분양정보 285건 + APT 잔여세대 508건 + 오피스텔·민간임대 124건을 전수로 훑어
  접수중·접수예정만 남긴 결과)
- 완전 정적(서버·DB 없음), 외부 라이브러리 0개, 폰트는 시스템 폰트 사용

## 실행

```bash
cd cheongyak-filter-app
python3 -m http.server 8000
# 브라우저에서 http://localhost:8000
```

`index.html`을 더블클릭하면 브라우저 보안(CORS) 때문에 JSON을 읽지 못합니다.
`app.js`는 `window.__CHEONGYAK_DATA__`가 있으면 그 데이터를 먼저 쓰므로, 오프라인 배포용으로는 CSS·JS·JSON을 인라인한 단일 HTML로 묶어 쓸 수 있습니다.

## 되는 것

| 기능 | 설명 |
|---|---|
| 내 조건 3초 입력 | 주택 수 / 거주지(8개 광역권) / 예치금 / 세대주 여부 → `localStorage`에 저장 |
| 예치금 입력 3단 | **50만 원 단위 칩**(없음·200만~500만+) + **10만 원 단위 슬라이더**(0~1,500만+) + **원 단위 직접 입력**(예: `3,500,000 원`)이 서로 동기화. 초기값은 무주택·경기·**2,000,000원** |
| 청약홈 신청 연결 | 카드·드로어에서 공고 유형에 맞는 청약홈 **청약신청 화면**으로 바로 이동(APT 1순위·2순위 / 무순위·잔여세대 / 임의공급 / 불법행위재공급 / 오피스텔 / 공공지원민간임대). 접수 예정·마감·조건 미달은 버튼이 **공고 보기**로 바뀌고 상태를 함께 표시 |
| **접수 시간 게이트** | 청약홈 접수는 **평일 09:00~17:30(KST)**. 이 시간 밖이거나 주말·공휴일이면 카드·드로어·연속 신청 모드의 **신청 버튼이 잠기고**(청약신청 화면으로 넘어가지 않음), 화면 위 띠에 `오전 9시부터 신청할 수 있어요 · 1시간 20분 남았어요`처럼 언제 열리는지가 나옵니다. `공고 보기`·공고문 PDF는 그대로 열립니다 |
| 전국 필터 | 서울·경기·인천·부산·울산·경남·대구·경북·대전·세종·충청·광주·전라·강원·제주를 8개 광역권 칩으로 선택, 판정은 시도 단위 |
| 스마트 필터 | 지원 가능·조건 미달·관심·전체, 마감 임박·발표일·분양가·물량·지역 정렬 |
| **마감 공고 숨김** | 접수 기간이 끝난 공고(`applyEnd` 경과, 그리고 마지막 접수일 17:30이 지나거나 주말·공휴일이라 오늘 접수할 수 없게 된 공고)는 **기본 목록(지원 가능·조건 미달·전체)·상단 카운트·연속 신청 모드에서 빠집니다**. 날짜가 지나 마감된 공고가 `listings.json`에 남아 있어도 화면에서 바로 거르고, 20초 주기 시각 확인에서 17:30·날짜 바뀸을 감지해 다시 그립니다. `관심`에 담아 둔 공고만 `관심` 탭에서 마감 상태(`접수 마감 · 공고 보기`, 오늘 마감이면 `오늘 접수 마감 · 공고 보기`)로 남습니다 |
| 불가 사유 배지 | `예치금 50만 원 부족 (300만 원 필요)`, `부산·울산·경남 거주자만 신청 가능 (현재 서울)` 처럼 이유를 그대로 표시 |
| 해당지역 우선 표시 | `서울·경기·인천 거주 — 기타지역` + `경기 해당지역 우선 — 남은 물량만` |
| 당첨자 발표일 중복 | 관심 체크한 공고의 **당첨자 발표일**(`winnersDate`)이 겹치면 경고 배너 + 카드 배지 (1인 1건 규칙). 모집공고일과는 다른 날짜로 판정 |
| 상세 드로어 | 공고문 원문 근거 인용, 일정 타임라인(모집공고 → 접수 → 당첨자 발표 → 계약 → 입주), 주택형별 공급 금액, 예치금·거주지·세대주 조건, 시행사·문의처, 공고문 PDF·청약홈 공고 상세·청약신청 화면 링크, 하단 고정 **청약홈에서 신청** 버튼 |
| 수익화 슬롯 | 상단·카드 사이 네이티브·하단·사이드 광고 자리 (`[광고/제휴 슬롯 예시]` 라벨) |
| **소득·자산 기준 실수치** | 공공분양·신혼희망타운·공공지원민간임대 공고문의 **자산보유기준(부동산·자동차)** 과 **도시근로자 월평균소득 %**를 카드 한 줄 + 상세 드로어 표로 표시. 가구원수(3인 이하~8인, 또는 1~8인)를 고르면 그 가구의 기준액이 바뀌고, 맞벌이 기준을 따로 보여 줍니다. 공고문을 확인하지 못한 건은 `원문 확인 필요`, 기준이 없는 건은 `기준 없음`으로 구분(추측 수치 없음) |
| **관심 연속 신청 모드** | `관심` 필터에서 마감이 급한 순서(접수중 → 접수예정)로 공고를 세우고, 각 단계마다 **청약홈 신청 열기**(유형별 정확한 신청 URL) + **신청 완료 체크**(localStorage) + 진행률(`1/2 신청 완료`)을 보여 줍니다. **신청 완료 체크는 접수 기간 중이고 내 조건을 충족한 공고에만** 붙습니다 — 접수 시작 전(D-n)·조건 미달 공고는 `공고 보기`(청약홈 공고 상세)만 열고 체크 버튼이 없습니다. 진행률 분모도 그런 신청 가능 공고만 세고, 신청 가능한 공고가 0건이면 `신청 가능 공고 없음`으로 표시합니다. 마감된 공고는 아예 올리지 않습니다. 청약홈 구조상 일괄 자동 신청은 불가능(단지별 주택형·자격 선택 + 전자서명)하다는 안내를 함께 표시 |
| 원문 미확인 표시 | 공고문에서 자격을 확인하지 못한 공고는 `원문 미확인` 배지 + `조건 미달`로 표시(추정으로 통과시키지 않음) |

## 소득·자산 기준 데이터

공고문 PDF의 표를 그대로 옮긴 값은 `data/income_asset.json` 에 공고번호(`houseManageNo`)별로 모아 둡니다.
`sync_applyhome.py` 는 이 파일을 먼저 보고, 없는 공고만 PDF에서 보수적으로 자동 추출합니다.

```jsonc
"incomeAsset": {
  "status": "확인",                 // 확인 | 기준 없음 | 원문 확인 필요
  "applies": "다자녀·노부모부양·…·전용 60㎡ 이하 일반공급",
  "generalNote": "전용 60㎡ 초과 일반공급은 소득·자산 기준이 없습니다.",
  "source": "입주자모집공고문 <표2> 자산보유기준 · <표4> 소득기준 (p.13~16)",
  "columns": ["3인 이하", "4인", "5인", "6인", "7인", "8인"],
  "incomeLabel": "전년도 도시근로자 가구당 월평균소득",
  "rows": [
    { "group": "일반공급(60㎡ 이하)", "label": "신생아 우선공급(50%)",
      "pct": 100, "dualPct": 140,
      "amounts": [7533763, 8802202, 9326985, 9906263, 10485541, 11064819],
      "dualAmounts": [10547268, 12323083, 13057779, 13868768, 14679757, 15490747] }
  ],
  "asset": { "realEstate": 215500, "car": 45420, "unit": "천원",
             "relaxedForBirth": { "realEstate1Child": 237050, "realEstate2Child": 258600,
                                  "car1Child": 49960, "car2Child": 54510 } },
  "checkedAt": "2026-11-26"
}
```

- `asset` 금액 단위는 공고문 표와 같은 **천원**입니다(215,500천원 = 2억 1,550만 원).
- `rows` 의 `amounts` 는 `columns` 순서와 1:1 대응입니다. `dualPct` 는 맞벌이(본인·배우자 모두 소득) 기준 퍼센트.
- 표 구조가 공고마다 달라 자동 추출이 어려운 건은 `data/income_asset.json` 에 사람이 원문을 보고 적고,
  PDF가 없거나 표를 못 찾으면 `status: "원문 확인 필요"` 로 남깁니다(수치를 지어내지 않습니다).

## 청약 접수 시간 — 평일 09:00~17:30 (KST)

청약홈 접수는 **한국 시간 평일 09:00~17:30**에만 열립니다. 근거는 청약홈
「인터넷 주택청약업무 운영시간」(주택청약 접수 09:00~17:30 · 이용일 **영업일**)이고,
입주자모집공고문도 유형(특별공급·1순위·무순위·임의공급·오피스텔·민간임대)과 상관없이
`청약신청 시간 : 09:00~17:30`으로 같습니다. 공고문에 함께 적힌 대로 **17:30은 '접수 완료' 기준**이라,
그 전에 주택형 선택·자격 입력·전자서명까지 끝나야 합니다.

### 언제 무엇이 잠기나

| 지금 시각(KST) | 화면 위 띠 | 카드·드로어 버튼 | 연결되는 곳 |
|---|---|---|---|
| 평일 09:00~17:30 | `지금은 청약 접수 시간이에요 · 오늘 17:30 마감` | `청약홈에서 신청하기` | 청약홈 청약신청 화면 |
| 17:00~17:30 | `…17:30 마감 · N분 남았어요` (주황) | 같음 | 같음 |
| 평일 00:00~09:00 | `오전 9시부터 신청할 수 있어요 · N시간 M분 남았어요` | `접수 시간 아님 · 09:00부터 신청` (잠금) | 누르면 안내만, 링크 없음 |
| 평일 17:30 이후 | `오늘 접수 시간(17:30)이 지났어요 · 내일 11/27 09:00부터…` | `접수 시간 아님 · 내일 11/27 09:00부터` | 누르면 안내만 |
| 토·일 | `주말에는 청약 접수가 없어요 · 월요일 11/30 09:00부터…` | 잠금 | 안내만 |
| 공휴일 | `공휴일(성탄절)에는 청약 접수가 없어요 · 월요일 12/28 09:00부터…` | 잠금 | 안내만 |

- **오늘이 마지막 접수일**인 공고는 17:30이 지나면 목록에서 빠집니다. `관심`에 담아 둔 공고는
  `관심` 탭에서 `오늘 접수 마감 · 공고 보기`로 남고, 드로어에 `오늘 접수 시간(17:30)이 지나 이 공고는 신청할 수 없어요`가 표시됩니다.
- 접수 기간 전(`접수 예정`)·후(`접수 마감`)는 원래대로 `공고 보기`이고, 시간 안내는 띠에만 나옵니다.
  `접수 마감` 공고는 기본 목록·연속 신청 모드에 올리지 않고(`관심` 탭에만 남김), 마감된 공고는
  상태 문구도 `접수 11/20~11/24 마감`으로 끝나고 `청약홈 로그인 후 신청` 같은 신청 안내를 붙이지 않습니다.
- 잠긴 버튼을 누르면 토스트로 이유와 다음 접수 시각을 알려 주고, **청약신청 화면 링크는 그리지 않습니다**
  (드로어 '원문 보기'의 `청약신청 화면`도 같은 시간에만 링크로 나옵니다).
- 접수 중(09:00~17:30)이 되는 순간, 20초마다 시각을 확인해 버튼이 자동으로 풀립니다.
  시각은 `Date.now()`에서 **UTC+9**로 계산하므로 기기 시간대와 상관없이 같게 동작합니다.

### 공휴일 표

`app.js`의 `HOLIDAYS`에 관공서 공휴일(주말 제외)을 둡니다. 2026년은 확정분, 2027년은
우주항공청 월력요항 기준이며 **임시공휴일은 반영 전**입니다(그날은 평일처럼 열리고, 실제 접수 가능
여부는 청약홈이 최종 판단). 표를 고칠 때는 `HOLIDAYS`만 수정하면 됩니다.

## 관심 연속 신청 모드

- 진입: 하단 관심 바의 **연속 신청 모드** 버튼(또는 `관심` 필터).
- 정렬: 접수중 → 접수예정 → 마감, 같은 상태면 접수 시작일 순.
- 각 단계: 공고명·지역·유형·D-day·신청 경로(APT 1순위/무순위/임의공급/오피스텔/민간임대)와
  `청약홈 신청 열기` 버튼. **지금 신청할 수 없는 공고**는 버튼이 `공고 보기`로 바뀌고
  **청약홈 공고 상세**(`detailUrl`)를 연다(오늘 접수 마감이면 `오늘 접수 마감 · 공고 보기`).
  마감·조건 미달·접수 예정 공고에서는 청약신청 화면으로 넘어가지 않습니다.
- **`신청 완료 체크`는 실제로 신청할 수 있는 공고에만** 붙습니다. 접수 기간 중(접수중)이면서
  내 조건(주택 수·거주지·예치금·세대주)을 충족한 공고가 그 대상이고, D-11·D-4처럼 **접수 시작 전**인
  공고와 **조건 미달** 공고는 공고만 볼 수 있으므로 체크 버튼이 없습니다. 접수 시간(09:00~17:30) 밖이어도
  접수 기간 중이면 신청 대상이므로 체크할 수 있습니다.
- 진행률(`N/M 신청 완료` + 진행 바)의 분모 M은 **신청 가능한 관심 공고 수**입니다. 신청 가능한 공고가
  하나도 없으면 숫자·진행 바 대신 `신청 가능 공고 없음`으로 표시하고, 접수가 시작되면 그 단계에 체크가
  나타난다고 안내합니다.
- 체크는 `localStorage['cheongyakddak:applied:v1']` 에 `{공고ID: 완료시각}` 으로 저장되고,
  진행률과 관심 바 요약(`신청 완료 1/2`)에 함께 반영됩니다. 이미 체크해 둔 공고는 그 뒤 조건을 바꿔
  신청 대상에서 빠져도 체크 표시가 남아 직접 해제할 수 있지만, 진행률 분모·분자에는 들어가지 않습니다.
  `신청 완료 체크 모두 지우기`로 초기화.
- 청약홈은 단지별 주택형·자격 선택과 매 건 전자서명이 필요해 한 번의 클릭으로 일괄 신청은 되지 않습니다.
  이 모드는 그 제약을 안내하면서 한 화면에서 차례대로 끝낼 수 있게 해 줍니다.

## 데이터 갱신


동작 방식

1. 청약홈의 세 목록(APT 분양정보 / APT 잔여세대 / 오피스텔·민간임대)을 끝 페이지까지 읽어
   모집공고일 8개월 전 ~ 4개월 후 구간의 공고를 모읍니다.
2. `접수 종료일 >= 오늘` 인 공고만 남깁니다(= 접수중·접수예정).
3. 각 공고의 **주요정보 팝업**에서 공급위치·공급규모·청약일정·주택형별 공급금액·입주예정월을 읽습니다.
4. 첨부된 **입주자모집공고문 PDF**를 내려받아 `신청자격` 문구에서
   무주택 여부·거주지 요건·세대주 요건을 뽑고, 근거 문장을 `evidence`로 남깁니다.
5. 예치금은 「주택공급에 관한 규칙」 85㎡ 이하 1순위 기준을 시도로 계산합니다

## 주의

- 이 앱은 **정보 제공용**이며 청약 대행이 아닙니다. 최종 자격은 공고문 원문으로 확인해야 합니다.
- 청약홈 접수는 **평일 09:00~17:30(KST)**이고 17:30은 접수 **완료** 기준입니다. 이 앱은 그 밖의 시간에
  신청 버튼을 잠그지만, 임시공휴일처럼 앱이 모르는 휴무일은 평일로 취급합니다. 최종 접수 가능 여부는
  청약홈이 판단합니다.
- 자격 판정은 공고문의 '신청자격' 문구를 규칙으로 옮긴 것입니다. `1주택 가능`은
  비규제지역 민영 일반공급 1순위에 무주택 제한이 없다는 뜻이고, 투기과열·청약과열지구는
  `무주택 전용`으로 판정합니다.
- 공공분양·민간임대는 소득·자산 기준이 함께 있습니다. 이 앱은 소득·자산을 입력받지 않으므로
  통과 판정이 곧 자격 충족은 아닙니다. 다만 2026-11-26부터는 공고문 표의 실제 기준액을
  카드·드로어에 보여 주므로, 본인 가구원수·소득·자산과 직접 비교할 수 있습니다.
- 공고가 마감되면 카드에 `접수 마감`으로 표시되고 정렬에서 뒤로 밀립니다.
